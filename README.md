# MyTab — Firefox 新标签页

一个**纯本地**的 Firefox 新标签页：时钟、问候、搜索、常用网站磁贴、WeTab 风格文件夹分组。
零账号、零追踪、无广告，所有数据只存在你的浏览器里。

## 使用方式

### 方式一：不装扩展，直接体验

双击 `index.html` 用 Firefox 打开即可（`file://` 下的数据独立保存，与扩展互不影响）。
> 注意：直开模式下「无痕窗口打开 / 收藏到书签」不可用。

### 方式二：装成 Firefox 扩展（真正替换新标签页）

1. Firefox 地址栏输入 `about:debugging#/runtime/this-firefox`
2. 点击「**临时载入附加组件…**」
3. 选择本目录下的 `manifest.json`
4. 按 `Ctrl+T` 打开新标签页 → 显示 MyTab

> **说明**：临时载入的扩展在 Firefox 重启后**会被卸载**（Firefox 关机时调用 `XPIProvider.cleanupTemporaryAddons()` 清理 `app-temporary` 位置的扩展），所以每次重启都要重新载入一次。
>
> **好消息：数据不会丢。** Firefox 按扩展 ID 固定分配 `moz-extension://` 的 origin UUID，并写进 profile 的 `extensions.webextensions.uuids`。所以只要扩展 ID 不变（`mytab@local.mytab`），重新载入后分组、磁贴、设置、图标缓存会**原样恢复**。
>
> 想彻底免去每次重载，见下文「持久安装（重启后不失效）」。

### 关于「Firefox 无法访问本地文件」的提示

如果你用**第三方「New Tab Override」插件**，并把「本地 HTML 文件 / 自定义网址」指向磁盘上的 `file:///…/index.html`，Firefox 会提示无法访问本地文件。这是预期行为：**扩展不允许把新标签页重定向到本机 `file://` 路径**，第三方插件因此建议你用 MAMP/XAMPP 等本地服务。

**本项目不受该限制**：HTML/CSS/JS 全部打包在插件内部（`moz-extension://` 协议），`background.js` 重定向到插件自己的 `index.html`，无需任何本地服务。

所以：**不要用第三方插件去指本地文件，直接载入本项目插件即可。** 若坚持使用第三方插件，则需把页面放到本地 HTTP 服务（例如 `python -m http.server 8848`，比 MAMP/XAMPP 更轻），再在插件里填 `http://127.0.0.1:8848/index.html`。

### 持久安装（重启后不失效）

**先说结论：官方版 Firefox 装不了未签名的 xpi。** 官方版构建里 `MOZ_REQUIRE_SIGNING=true` 是写死的（编译进 `omni.ja`），`about:config` 里把 `xpinstall.signatures.required` 改成 `false` 在官方版上**完全无效**（源码 `BrowserGlue.sys.mjs` 里是 `if (AppConstants.MOZ_REQUIRE_SIGNING) { signingRequired = true; }`，直接走不到读偏好那一步）。所以想在官方版里持久安装，只能走 AMO 签名。

三条路，按推荐顺序：

#### 方案 A：装一个 Firefox ESR（最省事，推荐）

ESR 是官方发布的长期支持版，**允许安装未签名扩展**（`MOZ_REQUIRE_SIGNING=false`），且和正式版**可以共存**（各自的安装目录和 profile 互相独立）。

> ⚠️ **ESR 安装器的两个坑（实测踩过）**：
>
> 1. **ESR 安装器默认装到 `C:\Program Files\Mozilla Firefox`**（和正式版同一个目录），不是 `…\Mozilla Firefox ESR`。它会把正式版**覆盖掉**。本机已踩过一次：ESR 装完后正式版被替换成 ESR 153.7.0。
> 2. **两个版本共用同一个卸载注册表键** `HKLM\…\Uninstall\Mozilla Firefox`，后装的会覆盖先装的条目，「应用和功能」里只能看到一个。
>
> 所以正确做法是：**先装正式版 → 再把 ESR 目录整个搬到 `C:\Program Files\Mozilla Firefox ESR` → 再补登记一个独立的注册表条目**。

**完整步骤（本机已验证走通）：**

1. 下载 [Firefox ESR 64-bit（简体中文）](https://www.firefox.com/zh-CN/download/all/desktop-esr/win64/zh-CN/)（下载链接是「latest」，会自动拿到当前 ESR 主线版本）
2. 先装好**正式版** Firefox（如果还没装）
3. 安装 ESR（`/S` 静默安装即可）。装完后它会覆盖正式版 —— **没关系，下一步会把两个版本分开**
4. 把 ESR 目录整个改名搬走：
   ```powershell
   Move-Item 'C:\Program Files\Mozilla Firefox' 'C:\Program Files\Mozilla Firefox ESR'
   ```
5. 把正式版装回原位（再跑一次正式版安装包即可）：
   ```powershell
   # 重新运行 Firefox Setup 160.0.exe /S
   ```
6. 给 ESR 补一个**独立的注册表条目 + 开始菜单快捷方式**（管理员 PowerShell）：
   ```powershell
   # 见 .preview/register-esr.ps1
   powershell -ExecutionPolicy Bypass -File .preview/register-esr.ps1
   ```
   脚本会写 `HKLM\…\Uninstall\Mozilla Firefox ESR`（注意名字多了 ` ESR`）并创建「Mozilla Firefox ESR」快捷方式，之后两个版本在「应用和功能」里就能并存。
7. 配置 ESR 的 profile（profile 名一般是 `xxxxxxxx.default-esr`）：
   ```powershell
   $p = "$env:APPDATA\Mozilla\Firefox\Profiles\<你的 .default-esr 目录>"
   ```
   在该目录建 `user.js`：
   ```js
   // 允许安装未签名的扩展（本项目自打包 xpi）
   user_pref("xpinstall.signatures.required", false);
   // 每次启动都扫描 profile 的 extensions/ 目录，把新 xpi 丢进去就能被识别
   // SCOPE_PROFILE = 1（见 AddonManager.sys.mjs）
   user_pref("extensions.startupScanScopes", 1);
   ```
8. 装 MyTab：`about:addons` → 齿轮 →「从文件安装附加组件…」→ 选 `mytab-3.0.1.xpi`
9. 之后每次升级扩展：把新的 xpi 拖进 ESR 的 `about:addons` 窗口即可覆盖安装

**验证持久生效**：关掉 ESR → 重新打开 → 按 `Ctrl+T`，新标签页应直接显示 MyTab，且 `about:addons` 里 MyTab 仍是「已启用」。

> **数据怎么带过去**：MyTab 的 localStorage 按 `moz-extension://<uuid>` 分区，而 uuid 是**按 profile** 分配的。想让 ESR 复用正式版的数据，把 `user.js` 里再加上：
> ```js
> user_pref("extensions.webextensions.uuids", "{...原 map..., \"mytab@local.mytab\":\"<正式版里的 uuid>\"}");
> ```
> 并把 `storage/default/moz-extension+++<uuid>/` 整个目录拷到 ESR profile 下对应位置。uuid 可在正式版的 `prefs.js` 里搜 `extensions.webextensions.uuids` 找到。

> ESR 一年内只做大版本更新，日常用完全够用。

#### 方案 C：Firefox Developer Edition / Nightly

和 ESR 一样允许未签名扩展，还能顺便用上调试工具。缺点是**会频繁更新**（Nightly 一天几次），不适合当日常浏览器。见 [Developer Edition 下载](https://www.firefox.com/channel/desktop/developer/)。

---

#### 各方案的数据会不会丢？

都不会。持久安装用的是同一个扩展 ID `mytab@local.mytab`，Firefox 因此分配同一个 `moz-extension://` origin UUID，profile 里 `storage/default/moz-extension+++<uuid>/ls/data.sqlite` 的 `mytab.v1` / `mytab.favicon.v1` 会继续被读写。

> ⚠️ 唯一会丢数据的情况：**换了扩展 ID**（改 `manifest.json` 的 `browser_specific_settings.gecko.id`）。Firefox 会分配新的 origin UUID，旧的 localStorage 就再也读不到了。改 ID 前请先用设置面板的「导出配置」备份。

**另一个例外**：`file://` 直开模式（方式一）。它的 localStorage 按**文件路径**分区（origin 是 `file:///E:/MyProject/MyTab/index.html`），所以项目目录一旦移动，旧路径的数据就再也读不到了 —— 扩展模式不受影响。

> **排查小抄**：想直接读 profile 里的 MyTab 配置，`data.sqlite` 的 `value` 列是 **Snappy 压缩**的（`compression_type=1`，Firefox 用了自己 vendored 的 snappy `RawUncompress`，不是标准 snappy 帧格式），4 字节前缀之后是 Snappy 裸块。直接用 Python 的 `snappy` 包解不开。

### 原理

**v3.0.0 起改用 Firefox 原生的新标签页接管机制**，不再用 `tabs.onCreated` 劫持重定向。

```json
"chrome_url_overrides": { "newtab": "index.html" },
"chrome_settings_overrides": { "homepage": "index.html" }
```

> ⚠️ **更正**：v3.0.0 之前的文档写「Firefox 不支持 `chrome_url_overrides.newtab`」—— **这是错的**。
> Firefox 从 **54 版（2017 年 6 月）** 就支持这个键了，只是当时用的人少、文档没跟上。
> 现在 AMO 上主流的新标签页扩展（New Tab Override v19 / Tabliss / Tabby）全部用这个键。

两个键各管一半，缺一不可：

| 键 | 接管范围 |
|---|---|
| `chrome_url_overrides.newtab` | `Ctrl+T` 新标签页 |
| `chrome_settings_overrides.homepage` | **工具栏「主页」按钮** + **`Ctrl+N` 新窗口**（Firefox 的新窗口开的是主页，不是新标签页） |

> 只写 `newtab` 的话，Home 按钮和新窗口仍然会显示 Firefox 自带的 Activity Stream ——
> 这正是 v2.x 那个 `tabs.onCreated` 重定向 hack 存在的原因（它顺带拦了 `about:home`）。

改用原生机制带来三个好处：

1. **不需要 `tabs` 权限**（v2.x 的重定向方案必须申请 `tabs` 才能读标签页 URL）；
2. **不会闪一下默认新标签页**再跳走（重定向方案一定会闪）；
3. **Firefox 会主动弹窗告知用户**：「An extension, %S, changed the page you see when you open a new tab.」
   —— 用户知情、可一键改回，这正好符合 AMO 政策对「改变新标签页」这类行为的要求。

`background.js` 因此不再监听 `tabs.onCreated` / `tabs.onUpdated`，只保留图标抓取、无痕窗口、收藏书签三件事。

## 分组功能（v1.4.0 引入，v1.5.0 移除未分组 / 分组选择）

磁贴按场景归档成**分组 / 文件夹**（参考 Edge / Chrome 扩展 WeTab 的做法）。**不再有「未分组」**：所有磁贴都必须归属一个真实分组；首次运行会自动创建一个「常用」分组存放默认网站。

分组导航采用 **WeTab 同款的左侧窄图标栏**：整条栏约 64px 宽，只放**灰色圆角图标磁贴**；栏高固定为**页面高度的 60%**并垂直居中，分组图标超出时在栏内用鼠标滚轮上下滚动；**没有顶部 Logo，也没有编辑模式按钮**；选中项使用**中性灰蓝**（不是黑色）。分组名不占宽度，悬停图标用 tooltip 显示名称 + 数量。

### 怎么用

| 操作 | 做法 |
|---|---|
| 新建分组 | 图标栏底部「＋」，或「主页」文件夹墙末尾的 **＋ 新建分组** 卡片 → 填名称、选图标 → 创建 |
| 进入分组 | 点左侧图标；或点「主页」视图里的文件夹卡片 |

- **左侧图标栏**：没有顶部 Logo；灰色圆角图标磁贴，**选中项为中性的灰蓝色**；图标顺序 = 分组顺序；**固定页面高度 60%，垂直居中**；分组过多时栏内滚轮滚动；底部只有「新建分组」和「设置」。
- **tooltip**：分组名和数量只在悬停时出现，所以栏宽只容纳图标；tooltip 右上提示「右键 编辑/删除」。
- **编辑入口**：右键图标（或右键文件夹卡片）→「编辑」，名称和图标在同一个弹窗里修改；没有单独的「更换图标」项。
- **删除**：右键图标 →「删除」；**组内磁贴会一起删除**，确认框会明确提示磁贴数量与不可恢复。
- **「主页」视图**：只有文件夹卡片墙（每张卡**顶部是分组图标 + 名称 + 数量，下方是组内前 4 个站点的真实图标**，2×2 固定方块）+ 末尾「＋ 新建分组」卡；不再有「未分组」散放磁贴条。
- **分组卡片预览**：固定 2×2 方块，组内 3 个、4 个或更多图标时尺寸都不变；图标区域留白缩小，站点图标更清晰。
- **分组视图**：不再有中间标题栏（分组名 / 网站数 / 添加按钮已移除），只保留该组的磁贴网格与独立分页器；添加磁贴走页面右键菜单。
- **窄屏（≤980px / ≤640px）**：图标栏进一步收窄到 58px / 54px，图标磁贴保持可点，tooltip 仍然可用。

### 数据与升级

- localStorage 顶层结构为 `groups: [{ id, name, icon }]` + `tiles: [{ id, name, url, icon, groupId }]`；**每个磁贴都有 `groupId`**，分组图标 `icon` 为图标库 id（如 `ad-4766846`）。
- **从旧版（emoji 图标）升级**：旧分组里的 `emoji` 会一次性迁移成图标库 id（见「分组图标库」的映射表），迁移后回写 localStorage，`emoji` 字段不再保留。
- **从 v1.4.x 升级**：老数据里没有 `groupId`（或指向已删除分组）的磁贴，会自动进入一个新分组——沿用旧「未分组」的自定义名称，否则叫 **「常用」**；一个磁贴都不会丢。
- **首次运行**：默认 6 个网站自动进入「常用」分组，主页展示「常用」文件夹卡片。
- `settings.currentGroup` 记住上次所在分组（`"all"` = 主页）；分组被删或 id 失效时自动回落到主页。
- 没有分组也没有磁贴时，主页只显示「新建分组」卡；此时右键「添加磁贴」会引导先新建分组。
- 删除分组会把组内磁贴一起删除。
- v1.4.2 的自定义分组图片已移除；旧数据里的 `image` 字段会被忽略，分组使用内置图标库。

## 配置导入 / 导出（v1.6.0 引入，v1.9.0 改为 ZIP 压缩包）

设置面板底部「数据备份」区：

| 操作 | 说明 |
|---|---|
| **导出配置** | 生成 `mytab-backup-YYYYMMDD-HHmm.zip`：**一个 ZIP 压缩包**，里面是配置文件（`mytab.json`）和你的背景图片（`background.xxx`） |
| **导出时包含背景图片** | **默认开启**（v1.9.0 起）：图片作为压缩包里的**独立文件**，配置 JSON 本身仍然很小；不想带就取消勾选 |
| **导入配置** | 选择压缩包 → 校验 → 弹出摘要（分组 / 磁贴 / 搜索引擎 / 自定义 AI 入口 / 背景图片）→ 确认后**覆盖当前全部配置**；**也兼容旧版导出的单个 JSON 文件** |

### 压缩包里有什么

```
mytab-backup-20261115-0002.zip
├── mytab.json        配置：分组、磁贴、自定义搜索引擎、自定义 AI 入口、外观设置
└── background.png    你当前的背景图片（取消勾选「包含背景图片」时没有这个文件）
```

- **背景图片不再以 base64 内联在 JSON 里**——配置里只记文件名（`settings.bg = { type: 'image', file: 'background.png' }`），图片本体是压缩包里的独立文件。这样 JSON 始终只有几 KB，图片也不再撑爆 localStorage 配额。
- 压缩包用**存储方式**（不压缩）打包：jpg / png 本身已经是压缩格式，再压一遍几乎没收益，却能让整个包保持在几百 KB。
- 压缩包是**标准 ZIP**（本地文件头 + 中央目录 + EOCD），资源管理器、WinRAR、7-Zip、`unzip` 都能直接打开；回归测试里用 Python 标准库 `zipfile` 做过互操作校验（CRC 逐条校验通过）。
- 导入时如果压缩包里**缺少图片文件**，背景会退回默认渐变，不会报错。

### 配置 JSON 里的字段

| 位置 | 字段 | 内容 |
|---|---|---|
| 顶层 | `aiEngines` | **自定义 AI 入口数组**（`{ id, name, url }`），与顶层的 `engines`（自定义搜索引擎）对称 |
| `settings` | `engineEdits` | 搜索引擎的**编辑覆盖表**（`{ 内置id: { name, url } }`） |
| `settings` | `aiEdits` | AI 入口的**编辑覆盖表**（`{ 内置id: { name, url } }`） |
| `settings` | `engineHidden` | 被删除的**内置搜索引擎 id 数组** |
| `settings` | `aiHidden` | 被删除的**内置 AI 入口 id 数组** |
| `settings` | `bg.file` | 背景图片在压缩包里的文件名（仅图片背景时存在） |

导入是**白名单式**的，脏数据会被自动丢掉，不会破坏页面：

- `settings` 只接受已知字段与合法取值（主题只认浅色 / 深色 / 跟随系统；行数钳制 1–4、列数 3–8；未知键直接丢弃）；
- **编辑覆盖表只接受 `{ name, url }` 两个字符串字段**：值不是对象、字段类型不对（名称 / 网址不是字符串）的整条丢弃；
- **隐藏列表只保留真实存在的内置 id**：未知 id 直接丢掉，避免存档无限膨胀；
- 背景只接受 `data:image/...;base64,` 开头的图片，**`data:text/html` 之类的内容会被拒绝**；压缩包里的文件名也只接受纯文件名（**带 `../` 路径的会被丢弃**）；
- 分组丢弃空名与重复 id，图标非法时回退到图标库里的默认图标；
- 磁贴丢弃非 `http(s)://` 的网址（`javascript:` 之类一律不要）；
- 搜索引擎必须同时有名称和含 `{q}` 的 URL；
- 导入后仍会跑一遍老数据迁移：分组 id 失效的磁贴自动归入「常用」分组，**一个磁贴都不会丢**。

导入确认框的内容也随之更新：

```
即将导入：

· 分组 N 个
· 磁贴 N 个
· 自定义搜索引擎 N 个
· 自定义 AI 入口 N 个
· 背景图片 background.png

导入会覆盖当前的全部配置（磁贴、分组、搜索引擎、AI 入口、外观）。
```

> 配置本身还是纯 JSON，可以自己看、自己改；想手动改的话，解压后编辑 `mytab.json` 再重新打包也能导入。

## 分组图标库

分组图标使用 **iconfont「Ant Design 官方图标库」**（[cid=9402](https://www.iconfont.cn/collections/detail?cid=9402)，官方图标库 / 免费）。该集合共 599 个图标，其中大量是品牌 Logo、箭头和填充变体，因此从中**精选 134 个适合做分组 / 分类的图形**，并补上中文名（Ant Design 原名为英文）。

## 图标自动获取原理（v1.2.0 修复，v3.0.0 去第三方）

v1.0 的问题：只靠 `<img>` 直连站点 `/favicon.ico`，且图片设置了 `loading="lazy"`——图片在 `onload` 之后才插入 DOM，离游离节点上的 lazy 图片永远不会开始加载，**图标永远不显示**。

v1.1/1.2 的修复：
1. **去掉 lazy 加载**，`<img>` 链式回退立即生效。
2. **后台脚本抓取（主力）**：借助 host 权限读取目标网页 HTML（超时 7s），解析 `<link rel="icon">`（含 `shortcut icon`，支持 SVG），按「页面声明的图标 → /favicon.ico → /favicon.png → /apple-touch-icon.png」顺序抓取，转成 dataURL 缓存到本地；全失败才回退字母圆。成功缓存的图标二次打开秒显示、离线也能显示。

> **v3.0.0 的改动**：回退链里的 **Google favicon 服务已彻底移除**，
> 现在只向**站点自身**请求 `/favicon.ico` → `/apple-touch-icon.png` → 首字母彩色圆。
> 原因有两个：一是那条链路会把**用户访问的域名发给 Google**，与本项目「零追踪」的定位冲突，
> 也会在 AMO 审核里被当成「传输与主功能无关的数据」；
> 二是抓图标已经需要主机权限了，主机权限改成**按站点申请的���选权限**后，
> 用户没授权的站点根本不会发出任何请求，回退链自然也就只剩站点自身。

## 权限说明（v3.0.0 起）

| 权限 | 用途 |
|---|---|
| `bookmarks` | 右键菜单「收藏到书签」（只创建，不读取已有书签） |
| `clipboardWrite` | 右键菜单「复制链接地址」（只写，不读剪贴板） |
| `optional_host_permissions: ["*://*/*"]` | **可选权限**，安装时不授予。用户添加某个站点的磁贴时，就**那一个站点**向用户申请访问权，用来读它的 `<link rel="icon">` 声明拿准图标。可随时在 `about:addons` → 权限里撤销，撤销后图标回退为首字母色块，其余功能不受影响 |

> v2.x 用的是 `tabs` + `host_permissions: ["<all_urls>"]`（安装即授予全站访问权）。
> v3.0.0 改成原生 `chrome_url_overrides` 接管新标签页后不再需要 `tabs`，
> `<all_urls>` 也降级成了按站点申请的可选权限 —— 装完扩展时 Firefox **不再提示**「读取所有网站数据」。

## 已知限制

- 无痕窗口打开需要 Firefox 允许该扩展在隐私窗口运行（`about:addons` → 详情 → 「在隐私窗口中运行」）；未获准时会提示失败。
- 部分站点（如开启反爬/防盗链）可能返回默认图标或 404，此时回退首字母。
- 分组只支持**一级**（组内不再嵌套子分组）；分组数量不设硬上限，侧栏列表超出高度时纵向滚动。
- 分组名只在**悬停 tooltip** 中显示；改名走**右键图标 →「编辑」**，不再支持双击就地改名（图标栏没有文字行）。
- 分组图标来自内置图标库（134 个单色 SVG，不可上传图片）；旧数据里的 emoji / 旧图标 id / `image` 会在升级时自动迁移。
- **删除分组会同时删除组内磁贴，不可恢复**；确认框会显示将被删除的磁贴数量。
- 左侧图标栏不再放编辑模式按钮；磁贴删除 / 编辑需进入编辑模式，**组内排序随时可拖动，不必先进入编辑**。
- 分组编辑 / 删除通过**右键图标**的菜单完成；键盘可用 Shift+F10 打开右键菜单。
- **分组顺序随时可调**：直接拖动左侧分组图标、或主页上的文件夹卡片即可排序，不需要先进入编辑模式。
- **不再有「未分组」**：所有磁贴都归属于一个分组；删除全部分组和磁贴后，主页只剩「新建分组」，此时添加磁贴会先引导新建分组。
- 农历、云同步、多设备账号不在 v1 范围（可按需追加）。
- **AI 对话站就是普通磁贴**：DeepSeek / MiniMax / 豆包 / Kimi / 通义千问在「常用」分组里，**点开就是对话页**（网页版对话拿不到搜索词，所以没有「带词打开」这种能力）；MyTab 不请求这些站点。
- **内置引擎的「编辑」是覆盖值**：改的是 `settings.engineEdits` 里的副本，**MyTab 自带的内置默认值不动**，内置条目也仍然标着「内置」。
- **删除内置引擎不是真删**：被删除的内置条目只是记进 `settings.engineHidden`（列表与下拉里不再显示），用设置底部的**「全部恢复默认」**可一并找回；自定义条目才是真的从本地存储移除。
- **搜索引擎强制要求 `{q}`**：搜索词无处安放，网址缺 `{q}` 会被拒绝保存。
- **导入配置会覆盖当前全部配置**（分组 / 磁贴 / 搜索引擎 / 外观），操作前建议先「导出配置」留一份备份；导入本身不可撤销。
- **「全部恢复默认」不可撤销**：它会清空当前配置（外观 / 分组 / 磁贴 / 搜索引擎），点之前有确认框提醒，但确认之后就找不回来了——先导出备份。
- **时钟默认 24 小时制**：v1.9.0 起默认 24 小时制；手动切过 12 小时制的用户会保留自己的选择（`hour12UserSet` 标记），没切过的（包括从旧版升级的）一律按 24 小时制显示。
- **默认背景是 ocean**（渐变列表里的第二个）：v2.0.0 起默认背景从 aurora 改成 ocean；「背景 · 本地图片」下的「恢复默认」也跟着回到 ocean。
- **背景图片是独立文件**：导出的压缩包里，背景图片是 `background.xxx` 独立文件，配置 JSON 只记文件名；因此**手改 JSON 时不能直接内联 base64**（会被当成非法背景丢掉），要改图就换压缩包里的图片文件。

## 版本号策略（语义化版本）

从 v1.6.0 起，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/) **MAJOR.MINOR.PATCH**，按**改动的性质**判定，而不是按改动行数：

| 级别 | 语义 | 什么时候用 |
|---|---|---|
| **MAJOR** | 破坏性变更 —— 旧数据 / 旧环境不再兼容 | 扩展权限或身份变化；localStorage 键名变化；**移除**设置项或存储字段；删掉仍在引用的界面元素 |
| **MINOR** | 向后兼容的新功能 —— 老数据照常能用 | **新增**设置项 / 存储字段 / 界面元素 / 后台接口 |
| **PATCH** | 向后兼容的修复 —— 不加功能、不动兼容面 | 样式、文案、修复、内部重构 |

- 打包脚本 `build-xpi.py` 会自动按上面的规则判定，并在报告里列出判断依据；需要人工覆盖时用 `--bump major|minor|patch`。
- **运行时文件与上一个包完全一致时不升版本、也不打包**——不产生空版本（比如只改了文档或构建脚本）。
- 判定规则有独立单元测试：`python .iconfont/test/test-semver.py`。
